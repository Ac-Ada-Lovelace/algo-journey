# 12113 题解详解：位压缩与状态搜索

## 题目背景

本题要求判断一个 5×9 的棋盘图案能否通过画 1-6 个正方形得到。每个正方形是 3×3 的空心边框。

## 整体思路

### 算法框架

1. **预处理阶段**：枚举所有可能的正方形组合（1-6个），将每种图案存入集合
2. **查询阶段**：读入测试数据，转换为统一格式，在集合中查找

### 核心技术：位压缩

使用一个 `long long` (64位) 整数表示整个 5×9 = 45 格的棋盘状态。

## 位压缩编码方案

### 棋盘到整数的映射

```
棋盘布局 (5×9，共45个位置):
行0: 位 0-8
行1: 位 9-17
行2: 位 18-26
行3: 位 27-35
行4: 位 36-44

映射公式：第 r 行第 c 列 → 位编号 = r × 9 + c
```

### `bitcont` 函数：输入转换

```cpp
void bitcont(lint & tar, int offset) {
    lint bit = 1;
    for(int i = 0; i < 9; ++i, bit = 1)
        if(temp[i] != ' ')
            tar = tar | (bit << (i + offset));
}
```

**功能**：将一行字符串转换为位表示

- `offset` = 行号 × 9（标识当前处理第几行）
- 若 `temp[i]` 不是空格，则将第 `(i + offset)` 位设为1
- 使用 `|=` (OR) 操作累加多行数据

**示例**：

```
第2行（offset=18）第3列有字符
→ 设置第 (3 + 18) = 21 位为1
→ tar |= (1LL << 21)
```

## 正方形位置编码

### 可放置位置分析

```cpp
const int point[] = {0,2,4,9,11,13,18,20,22};  // 9个正方形左上角位置
```

**为什么是这9个位置？**

5×9 棋盘上，3×3 正方形需要占据3行3列：

- 行方向起始位置：0, 1, 2（共3种，因为0+3=3, 1+3=4, 2+3=5刚好）
- 列方向起始位置：0, 2, 4（共3种，注意间隔为2）

```
位置编号规律：
行0: 0,   2,   4
行1: 9,   11,  13  (9 = 1×9)
行2: 18,  20,  22  (18 = 2×9)

公式：point[i] = (i/3) × 9 + (i%3) × 2
```

### 正方形形状定义

```cpp
const int one[]  = {1,3,9,13,18,22,19,21};  // 需要置1的8条边
const int zero[] = {10,11,12,20};           // 需要置0的4个内部格子
```

**相对偏移示意图**（以左上角为基准点0）：

```
3×3 正方形的相对位置编号：
 0   1   2
 9  10  11
18  19  20

空心边框的8条边：
 ×   1   2
 9   ×  11
18  19  20

对应 one[] = {1, 2, 9, 11, 18, 19, 20}
```

**注意**：实际代码中 `one[]` 数组可能包含更多位置或不同编码，具体取决于题目对正方形的定义。关键是理解 **相对偏移** 的思想。

内部需要清空的4个格子：

```
10, 11, 12, 20
```

## `draw` 函数：位操作核心

```cpp
void draw(int now, lint & tar) {
    int cur = point[now];  // 获取正方形左上角的绝对位置
    lint bit = 1;

    // 第一步：OR 操作设置边
    for(int i = 0; i < 8; ++i, bit = 1)
        tar = tar | (bit << (one[i] + cur));

    // 第二步：AND NOT 操作清空内部
    for(int i = 0; i < 4; ++i, bit = 1)
        tar = tar & (~(bit << (zero[i] + cur)));
}
```

### 位操作技巧解析

#### 1. 设置位为1（画边）

```cpp
tar |= (1LL << k)  // 将第k位设为1，不影响其他位
```

#### 2. 设置位为0（清空内部）

```cpp
tar &= ~(1LL << k)  // 将第k位设为0，不影响其他位
```

**分解步骤**：

- `1LL << k`：创建只有第k位为1的掩码
- `~(1LL << k)`：取反，只有第k位为0，其余为1
- `tar & ...`：保留其他位，只清除第k位

#### 3. 为什么循环中有 `bit = 1`？

```cpp
for(int i = 0; i < 8; ++i, bit = 1)
```

- 循环体内可能修改 `bit` 的值（虽然这里没有）
- 每次迭代重置为1，确保 `bit << offset` 正确
- 这是一种防御性编程习惯

### 为什么先画边再清空内部？

**处理重叠的关键**：

- 当两个正方形重叠时，后画的边可能覆盖前面正方形的内部
- 先用 OR 添加所有边
- 再用 AND NOT 清空自己的内部，保证空心

**示例**：

```
正方形A的边可能在正方形B的内部区域
→ 画B时先加边（保留A的边）
→ 再清空B的内部（不影响A的边）
```

## DFS 搜索策略

```cpp
void dfs(int d, lint cur) {
    if(d == maxd) {
        buffer.insert(cur);  // 达到指定数量，存入集合
        return;
    }
    for(int i = 0; i < 9; ++i) {
        if(vis[i]) continue;  // 跳过已使用的位置
        lint old = cur;
        draw(i, cur);         // 在位置i画正方形
        vis[i] = true;
        dfs(d + 1, cur);      // 递归下一层
        cur = old;            // 回溯恢复
        vis[i] = false;
    }
}
```

### 搜索树分析

```
层数 d=0: 选择第1个正方形位置（9种选择）
层数 d=1: 选择第2个正方形位置（8种选择）
...
层数 d=maxd-1: 选择第maxd个位置

总状态数约为：P(9,1) + P(9,2) + ... + P(9,6)
```

### 去重机制

```cpp
set<lint> buffer;  // 使用 set 自动去重
```

**为什么会有重复？**

- 不同的绘制顺序可能产生相同的最终图案
- 例如：先画(0,0)再画(2,2) 等价于 先画(2,2)再画(0,0)

**set 的优势**：

- 自动去重，无需手动判断
- 基于红黑树，插入和查找都是 O(log n)
- 整数比较非常快

## 主函数：预处理与查询

```cpp
int main() {
    // 预处理：枚举1-6个正方形的所有组合
    for(maxd = 1; maxd <= 6; ++maxd)
        dfs(0, 0);

    int cont = 0;
    while(getline(cin, temp)) {
        lint target = 0;
        if(temp[0] == '0') break;

        // 读取5行，转换为位表示
        bitcont(target, 0);
        for(int i = 1; i <= 4; ++i) {
            getline(cin, temp);
            bitcont(target, i * 9);
        }

        // 查询是否存在
        printf("Case %d: ", ++cont);
        if(buffer.count(target) == 1)
            printf("Yes\n");
        else
            printf("No\n");
    }
    return 0;
}
```

### 时间复杂度分析

1. **预处理**：
   - 状态数：C(9,1) + C(9,2) + ... + C(9,6) ≈ 2^9 = 512（实际更少）
   - 每个状态需要画 O(maxd) 个正方形
   - 总时间：O(状态数 × maxd × 正方形大小) ≈ O(512 × 6 × 12) ≈ 37k 操作

2. **查询**：
   - 转换输入：O(45)
   - set 查找：O(log n) ≈ O(10)
   - 总计：O(测试用例数 × 55)

## 位压缩的优势总结

### 1. 空间效率

- **位压缩**：8字节（1个 long long）
- **数组存储**：45字节（45个 char）
- **节省率**：82%

### 2. 时间效率

- **整数比较**：O(1)，一条CPU指令
- **数组比较**：O(n)，需要循环45次
- **哈希计算**：整数天然是哈希值

### 3. 代码简洁性
