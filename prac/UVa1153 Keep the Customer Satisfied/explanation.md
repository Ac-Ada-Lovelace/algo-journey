## 问题描述

### 题意概括
钢铁厂有 n 个订单，每个订单有两个属性：
- **q**: 生产所需时间（秒）
- **d**: 截止日期（秒）

**约束条件**：
- 工厂一次只能处理一个订单
- 接受的订单必须在截止日期前完成
- 生产 q 吨钢需要恰好 q 秒（吞吐量为 1）

**目标**：最大化接受的订单数量（最小化拒绝的订单数）

### 示例

| 订单 | 耗时(q) | 截止日期(d) |
|------|---------|-------------|
| J1   | 6       | 8           |
| J2   | 4       | 9           |
| J3   | 7       | 15          |
| J4   | 8       | 20          |
| J5   | 3       | 21          |
| J6   | 5       | 22          |

**最优解**：接受 4 个订单（J2, J3, J5, J6），拒绝 J1 和 J4

执行顺序：
```
J2: [0, 4]   完成时间 4  ≤ 9  ✓
J3: [4, 11]  完成时间 11 ≤ 15 ✓
J5: [11, 14] 完成时间 14 ≤ 21 ✓
J6: [14, 19] 完成时间 19 ≤ 22 ✓
```

## 问题分析思路

### 第一步：识别问题类型

这是一个**单机调度问题**（Single Machine Scheduling）：
- 有 n 个任务
- 每个任务有处理时间和截止日期
- 机器一次只能处理一个任务
- 目标：最大化完成的任务数量

在算法竞赛中，关键词识别：
- "最大化/最小化某个数量"
- "截止日期约束"
- "单一资源"

这通常提示：**贪心算法** 或 **动态规划**

### 第二步：思考DP是否可行

**DP状态定义尝试**：
```
dp[i][t] = 考虑前 i 个任务，当前时间为 t 时，最多能完成的任务数
```

**问题**：
- i 的范围：n ≤ 800,000
- t 的范围：截止日期 < 2×10^6
- 状态空间：O(n × max_time) = O(1.6 × 10^12) —— **爆炸！**

**结论**：DP 不可行，考虑贪心算法。

### 第三步：寻找贪心策略

贪心算法需要回答：**每一步应该做什么选择？**

#### 问题1：任务处理顺序

**直觉思考**：
- 截止日期早的任务应该先做？
- 耗时短的任务应该先做？
- 还是其他标准？

**关键性质**（题目hint给出）：
> 在最优解中，接受的任务应该按**截止日期非递减顺序**执行。

#### 为什么按截止日期排序？

**定理1**：存在最优解，其中被接受的任务按截止日期非递减顺序排列。

**证明**（交换论证法）：

假设最优解中，存在两个相邻任务 Ti 和 Tj，满足：
- Ti 排在 Tj 前面
- di > dj（Ti 的截止日期更晚）

考虑交换这两个任务的顺序：

```
原顺序：... → Ti(qi, di) → Tj(qj, dj) → ...
        完成时间：  t + qi        t + qi + qj

交换后：... → Tj(qj, dj) → Ti(qi, di) → ...
        完成时间：  t + qj        t + qi + qj
```

**分析交换的影响**：

1. **Tj 的完成时间**：从 `t + qi + qj` 变成 `t + qj`
   - 完成时间**提前**了
   - 原本满足 `t + qi + qj ≤ dj`，现在仍然满足 `t + qj ≤ dj`

2. **Ti 的完成时间**：从 `t + qi` 变成 `t + qi + qj`
   - 完成时间**延后**了
   - 但截止日期从 dj 变成 di，且 di > dj
   - 原本满足 `t + qi ≤ di`，现在要检查 `t + qi + qj ≤ di`
   - 因为 di > dj，所以 `t + qi + qj ≤ dj` 的约束更严格
   - 如果原来 Tj 能满足截止日期，现在 Ti 也能满足

3. **后续任务**：不受影响（总时间相同）

**结论**：交换后解仍然可行，不会变差。因此，不失一般性地假设最优解按截止日期排序。

#### 问题2：遇到冲突时拒绝哪个任务？

按截止日期排序后，依次考虑每个任务。当发现无法按时完成时，有两个选择：

1. **拒绝当前任务**，继续处理后续任务
2. **拒绝某个已接受的任务**，接受当前任务

**关键问题**：如果选择拒绝已接受的任务，应该拒绝哪个？

**直觉**：拒绝耗时最长的任务！

**原因**：
- 目标是最大化完成的任务**数量**（不是最小化总耗时）
- 拒绝耗时长的任务，能为后续任务腾出更多时间
- 后续任务截止日期更晚，更容易完成
- 用多个短任务替换一个长任务，能增加完成数量

**例子对比**：

```
当前状态：已接受 {3秒, 5秒, 8秒}，总耗时 16秒
当前任务：2秒，截止 15秒
问题：16 > 15，超时了！

方案1：拒绝耗时8秒的任务
  新状态：{3秒, 5秒, 2秒}，总耗时 10秒
  剩余空间：5秒，可以接受多个小任务

方案2：拒绝耗时3秒的任务
  新状态：{5秒, 8秒, 2秒}，总耗时 15秒
  剩余空间：0秒，几乎不能接受新任务

方案3：拒绝当前2秒的任务
  新状态：{3秒, 5秒, 8秒}，总耗时 16秒
  但后续任务的截止日期≥15，可能有机会
```

**分析**：方案1最优，为后续留出最多可能性。

## 算法设计

### Hodgson-Moore 算法

```
算法：最大化完成任务数

输入：n 个任务，每个任务 (qi, di)
输出：最多能完成的任务数量

步骤：
1. 将所有任务按截止日期 di 升序排序
2. 初始化：
   - 已接受任务集合 S = ∅
   - 当前时间 t = 0
   - 最大堆 H（存储已接受任务的耗时）
3. 对每个任务 (qi, di)（按排序顺序）：
   a) 尝试接受：t = t + qi，将 qi 加入堆 H
   b) 如果 t > di（超过截止日期）：
      - 从 H 中取出最大值 qmax（耗时最长的任务）
      - 拒绝该任务：t = t - qmax
4. 返回 |H|（堆中剩余任务数）
```

### 关键数据结构

**最大堆（Priority Queue）**：
- 存储已接受任务的耗时
- 支持 O(1) 查找最大值
- 支持 O(log n) 插入和删除

```cpp
priority_queue<int> accepted;  // 默认是最大堆
```

### 算法伪代码

```python
def hodgson_moore(tasks):
    # 按截止日期排序
    tasks.sort(key=lambda x: x.deadline)

    accepted = MaxHeap()  # 最大堆
    current_time = 0

    for (duration, deadline) in tasks:
        # 尝试接受任务
        current_time += duration
        accepted.push(duration)

        # 检查是否超时
        if current_time > deadline:
            # 拒绝耗时最长的任务
            longest = accepted.pop()
            current_time -= longest

    return len(accepted)
```

## 正确性证明

### 定理：Hodgson-Moore 算法返回最优解

我们需要证明两个性质：
1. **贪心选择性质**：局部最优选择存在于全局最优解中
2. **最优子结构**：问题的最优解包含子问题的最优解

### 证明1：贪心选择性质

**引理**：在任何最优解中，如果需要拒绝任务，拒绝耗时最长的任务不会使解变差。

**证明**（交换论证法）：

设算法在处理前 k 个任务后，状态为：
- 接受任务集合：A = {T1, T2, ..., Tm}
- 当前任务：Tk+1
- 发现超时：∑(Ti ∈ A) qi + qk+1 > dk+1

算法选择：拒绝 Tmax（A ∪ {Tk+1} 中耗时最长的任务）

假设存在最优解 O，在相同情况下拒绝了 Tx（Tx ≠ Tmax）。

**情况1**：Tx = Tk+1（最优解拒绝当前任务）
- 如果 qmax = qk+1，则算法和最优解一致
- 如果 qmax > qk+1，则算法拒绝 qmax ∈ A

构造新解 O'：
- 用 Tk+1 替换 Tmax
- 因为 qk+1 < qmax，所以总耗时减少
- 前 k 个任务的截止日期都 ≤ dk+1
- 所有任务仍然满足截止日期
- O' 的任务数 = O 的任务数

**情况2**：Tx ∈ A（最优解拒绝已接受的某个任务）
- 比较 qmax 和 qx

如果 qmax > qx：
- 算法拒绝 qmax，剩余耗时更少
- 为后续任务留出更多空间
- 不会比 O 差

如果 qmax = qx：
- 算法和最优解等效

**结论**：算法的贪心选择不会比任何最优解差。

### 证明2：最优子结构

**引理**：如果前 k 个任务的解是最优的，那么前 k+1 个任务的解可以基于它构造。

**证明**（数学归纳法）：

**基础情况**：k = 0
- 前 0 个任务，最优解为空集，正确 ✓

**归纳假设**：假设前 k 个任务的解 Sk 是最优的

**归纳步骤**：考虑第 k+1 个任务

1. 如果 tk + qk+1 ≤ dk+1：
   - 可以接受 Tk+1
   - Sk+1 = Sk ∪ {Tk+1}
   - |Sk+1| = |Sk| + 1，是最优的

2. 如果 tk + qk+1 > dk+1：
   - 需要拒绝一个任务
   - 算法拒绝 Tmax

   假设存在更好的选择，拒绝 Tx，使得后续能接受更多任务。

   因为 qmax ≥ qx：
   - 拒绝 Tmax 后，剩余时间 ≥ 拒绝 Tx 后的剩余时间
   - 拒绝 Tmax 的解不会比拒绝 Tx 的解差
   - 矛盾！

**结论**：算法的递推构造是最优的。

### 完整性证明

结合贪心选择性质和最优子结构：
- 每一步的选择都是最优的
- 子问题的最优解构成原问题的最优解
- 因此，算法返回全局最优解 ✓

## 实现细节

### 完整代码

```cpp
// UVa1153 Keep the Customer Satisfied
#include <bits/stdc++.h>
using namespace std;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int T;
    cin >> T;

    for (int t = 0; t < T; t++) {
        if (t > 0) cout << '\n';  // 测试用例之间空行

        int n;
        cin >> n;

        // 读取所有订单: (耗时, 截止日期)
        vector<pair<int, int>> orders(n);
        for (int i = 0; i < n; i++) {
            cin >> orders[i].first >> orders[i].second;
        }

        // 步骤1: 按截止日期排序
        sort(orders.begin(), orders.end(),
             [](const pair<int,int>& a, const pair<int,int>& b) {
                 return a.second < b.second;
             });

        // 步骤2: 贪心选择 + 最大堆
        priority_queue<int> accepted;  // 最大堆
        int current_time = 0;

        for (int i = 0; i < n; i++) {
            int duration = orders[i].first;
            int deadline = orders[i].second;

            // 尝试接受当前订单
            current_time += duration;
            accepted.push(duration);

            // 如果超时，拒绝耗时最长的订单
            if (current_time > deadline) {
                int longest = accepted.top();
                accepted.pop();
                current_time -= longest;
            }
        }

        cout << accepted.size() << '\n';
    }

    return 0;
}
```

### 关键实现技巧

#### 1. 为什么用最大堆？

```cpp
priority_queue<int> pq;  // 默认最大堆
```

需求分析：
- **查找最大值**：O(1)
- **插入元素**：O(log n)
- **删除最大值**：O(log n)

最大堆完美匹配需求！

#### 2. 排序比较函数

```cpp
sort(orders.begin(), orders.end(),
     [](const pair<int,int>& a, const pair<int,int>& b) {
         return a.second < b.second;  // 按截止日期升序
     });
```

Lambda表达式简洁高效。

#### 3. 边界情况处理

- **空输入**：n = 0，输出 0
- **所有任务都能完成**：堆中有 n 个任务
- **所有任务都不能完成**：理论上不可能（至少能完成耗时最短的一个）

## 复杂度分析

### 时间复杂度

1. **读取输入**：O(n)
2. **排序**：O(n log n)
3. **主循环**：
   - 迭代 n 次
   - 每次：
     - 插入堆：O(log n)
     - 可能删除：O(log n)
   - 总计：O(n log n)

**总时间复杂度**：O(n log n)

### 空间复杂度

1. **存储订单**：O(n)
2. **堆空间**：O(n)（最多 n 个元素）

**总空间复杂度**：O(n)

### 性能评估

对于 n = 800,000：
- O(n log n) ≈ 800,000 × 20 ≈ 16,000,000 次操作
- 现代计算机每秒约 10^8 ~ 10^9 次操作
- 运行时间：约 0.1 秒，非常高效！

## 通用方法论

### 如何识别和解决贪心问题？

#### 步骤1：问题特征识别

贪心算法适用的问题通常具有以下特征：

**关键词**：
- 最大化/最小化某个目标
- "尽可能多"、"最少次数"
- 有资源约束
- 需要做一系列决策

**例子**：
- 活动选择问题
- 区间调度问题
- Huffman编码
- 最小生成树（Kruskal、Prim）
- 单源最短路径（Dijkstra）

#### 步骤2：寻找贪心策略

**思考框架**：

1. **排序**：能否通过排序简化问题？
   - 按什么属性排序？
   - 排序后有什么性质？

2. **局部选择**：每一步应该选择什么？
   - 最大/最小的？
   - 最早/最晚的？
   - 性价比最高的？

3. **反例测试**：用小例子验证
   - 找反例推翻策略
   - 修正策略

#### 步骤3：证明正确性

贪心算法**必须证明**正确性（否则可能只是启发式算法）！

**证明方法**：

1. **交换论证法**（Exchange Argument）
   - 假设最优解与贪心解不同
   - 交换某些选择，使其更接近贪心解
   - 证明交换后解不会变差
   - 反复交换，最终得到贪心解也是最优解

2. **归纳法**（Induction）
   - 证明每一步的贪心选择保持最优性
   - 基础情况 + 归纳步骤

3. **反证法**（Contradiction）
   - 假设贪心解不是最优解
   - 推导出矛盾
   - 因此贪心解是最优的

#### 步骤4：实现优化

选择合适的数据结构：
- 需要快速查找最大/最小值？→ 堆
- 需要快速查找/插入/删除？→ 平衡树
- 需要快速合并集合？→ 并查集

### 常见贪心问题类型

#### 1. 区间调度问题

**特征**：
- 有多个区间/活动
- 每个有开始和结束时间
- 资源有限（如单机器）

**策略**：
- 按结束时间排序
- 贪心选择最早结束的

**例题**：
- 活动选择问题
- 会议室安排

#### 2. 带截止日期的调度

**特征**：
- 任务有截止日期
- 目标：最大化完成数/最小化延迟

**策略**：
- 按截止日期排序
- 使用堆维护已选任务

**例题**：
- UVa1153（本题）
- 最小延迟调度

#### 3. 背包类问题

**特征**：
- 有容量限制
- 每个物品有价值和重量

**策略**：
- 分数背包：按性价比排序
- 0-1背包：需要DP（贪心不适用）

#### 4. 最优构造问题

**特征**：
- 构造某种结构使得代价最小

**策略**：
- Huffman编码：合并最小的两个
- MST：选择最小边（Kruskal）或最近点（Prim）

### 贪心 vs 动态规划

| 特征 | 贪心算法 | 动态规划 |
|------|---------|---------|
| 决策方式 | 每步做局部最优选择 | 枚举所有可能，记忆化 |
| 子问题重叠 | 不需要 | 需要 |
| 最优子结构 | 需要 | 需要 |
| 正确性 | 需要严格证明 | 通常递推正确 |
| 时间复杂度 | 通常 O(n log n) | 通常 O(n²) 或更高 |
| 实现难度 | 简单 | 中等到困难 |

**何时用贪心？**
- 能找到明确的贪心策略
- 能证明正确性
- DP 状态空间太大

**何时用DP？**
- 贪心策略不正确
- 子问题有重叠
- 需要枚举多种选择

## 总结

### Hodgson-Moore 算法核心要点

1. **问题特征**：单机调度，带截止日期，最大化完成数
2. **关键性质**：最优解按截止日期排序
3. **贪心策略**：超时时拒绝耗时最长的任务
4. **数据结构**：最大堆维护已接受任务
5. **时间复杂度**：O(n log n)

### 直觉理解

**生活类比**：

你是餐厅老板，今天收到很多外卖订单：
- 每个订单有"准备时间"和"送达时间"
- 厨房只有一个炉灶（单机）
- 你想尽可能多接订单（赚钱）

**策略**：
1. 先按送达时间排序（先做急的）
2. 依次尝试接单
3. 发现来不及？就取消之前接的"最耗时"的订单
4. 原因：取消大订单，能腾出时间做几个小订单，赚更多单数

这就是 Hodgson-Moore 算法！

- 交换论证法：贪心算法证明的利器
- 数据结构：好的数据结构是算法效率的关键

**问题解决**：
