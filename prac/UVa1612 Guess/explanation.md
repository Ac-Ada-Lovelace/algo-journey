【题目概览】

- 比赛有 3 道题，n 名选手（ID 为 1..n）。最终名次按三题总分排序，总分高者名次高，总分相同则 ID 较小者名次更高。
- 已知每个选手在三道题上若非完全做错时可能获得的分数；如果某题完全做错，则该题得分为 0。给出一组预测的最终排名顺序，需判断这组名次是否可能出现。

【输入格式：逐句解释】

- 输入包含多组测试。
- 每组的第一行是整数 n（n ≤ 16384），表示参赛选手数量。
- 接下来的 n 行中，第 i 行包含三个实数 a, b, c（0 ≤ a, b, c < 1000，且最多保留 2 位小数），分别表示选手 i 在三道题上如果没有完全做错时可以得到的分数；若某题完全做错，该题得分为 0。
- 随后一行包含 n 个整数，表示从第 1 名到第 n 名的选手 ID 顺序（即给出的预测最终排名）。
- 输入以只包含一个 0 的行作为结束标记，该行不属于任何测试数据。

【输入格式（结构化摘要）——字段清单形式】

字段顺序：

1. 第 1 行：n
   - 含义：选手人数。
   - 类型：整数。
   - 取值范围：0（仅作为结束标记）或 1..16384。
   - 数据保证：n = 0 表示输入结束，不构成一组测试。

2. 第 2 行至第 n+1 行：a b c
   - 含义：选手 i 在三道题上若非完全做错时的可能得分。
   - 类型：实数（可为整数或小数，至多两位小数）。
   - 取值范围：0 ≤ a, b, c < 1000。
   - 数据保证：题面明确最多两位小数；完全做错则该题得分为 0。

3. 第 n+2 行：n 个整数
   - 含义：按从第 1 名到第 n 名给出的选手 ID 顺序（预测的最终排名）。
   - 类型：整数。
   - 范围：应为 1..n 内的 ID；题面未特别声明是否一定为排列（默认视为给定的排名顺序）。
   - 特别说明：此行为当前测试数据的排名列表。

多组输入：

- 是否多组：是。
- 每组格式：如上 1~3 项。
- 终止条件：读到仅含 0 的行。
- 终止行是否需要处理：否，0 行仅为结束标志。

隐含条件 / 数据保证：

- 总分决定排名，总分相同则 ID 较小者排名更高（题面明示）。
- 题面未说明 a, b, c 是否可能为负数，已给出范围为非负小于 1000。

【输出格式】

- 对每组数据：若给定的排名可能实现，输出最低名次选手（即排名最后一名）的“最高可能总分”，保留两位小数；否则输出 `No solution`（不带引号）。
- 题面未直接说明前缀格式，但样例使用 `Case X: <结果>` 形式。

【样例输入输出（完整引用 + 输入部分解释）】
样例输入：

```
3
100 200 300
100 200 300
100 200 300
1 2 3
3
100 200 300
100 200 300
100 200 300
3 2 1
0
```

样例输出：

```
Case 1: 600.00
Case 2: 400.00
```

样例输入行解释：

- 第 1 组：n=3；三行分数均为(100,200,300)；排名顺序为 1,2,3（按名次列出 ID）。
- 第 2 组：n=3；分数同上；排名顺序为 3,2,1。
- 末行 0 表示输入结束。

【关键假设 / 陷阱】

- 总分相同必须按 ID 从小到大排前（影响可行性判断）。
- 输出需保留两位小数；不可省略或多出精度。
- 虽未明示输出前缀格式，但样例使用 `Case k:`，实现时应遵循样例格式。
- a, b, c 最多两位小数且非负小于 1000，完全做错的题得分为 0。
- 排名行应包含 n 个 ID，题面未声明必为 1..n 的全排列；需要按题意给定顺序判断可行性。

【解法提示（可选）】

- 可建模为可行性判定并同时最大化最后一名总分的线性规划/最大流变体：给每题是否得分的二元选择，利用排序约束限制总分区间；可二分最后一名总分并验证可行性。
