【题目概览】

- KTV 剩余时间内挑歌：每首歌只能唱 0 次或 1 次且必须唱满设定长度，唱完马上开始下一首；还可以选择一首长度为 678 秒的《劲歌金曲》。目标是优先让唱的歌数最多，若并列则总时长最大。

【输入格式：逐句解释】

- 第一行一个整数 T (T ≤ 100)，表示测试用例数量。
- 每个测试用例第一行给两个正整数 n, t (1 ≤ n ≤ 50, 1 ≤ t ≤ 10^9)，表示候选歌曲数量（不含《劲歌金曲》）和剩余时间（秒）。
- 每个测试用例第二行给出 n 个正整数，表示每首候选歌曲的长度（秒）。每个长度都小于 3 分钟；长度指想唱的片段长度，可以视为被“截断”后的时长。
- 题面保证所有歌（包含《劲歌金曲》的 678 秒）长度之和严格大于 t。

【输入格式（结构化摘要）——字段清单形式】

字段顺序：

1. 第 1 行：T
   - 含义：测试用例数量
   - 类型：整数
   - 取值范围：1 ≤ T ≤ 100
   - 数据保证：无额外保证

2. 对于每个测试用例的第 1 行：n t
   - 含义：候选歌曲数量（不含《劲歌金曲》）、剩余时间（秒）
   - 类型：整数，整数
   - 取值范围：1 ≤ n ≤ 50，1 ≤ t ≤ 10^9
   - 数据保证：无额外保证

3. 对于每个测试用例的第 2 行：n 个整数（各首歌长度）
   - 含义：n 首候选歌各自的演唱时长（秒），每首可选唱满或不唱
   - 类型：整数序列，长度 n
   - 取值范围：每个长度 < 180 秒（小于 3 分钟）
   - 数据保证：可以将歌曲剪裁到该长度

多组输入：

- 是否多组：是，由 T 控制
- 每组格式：一行 n t，下一行 n 个长度
- 终止条件：读完 T 组
- 终止行是否需要处理：否

隐含条件 / 数据保证：

- 所有歌（含固定的《劲歌金曲》时长 678 秒）长度总和严格大于 t。
- 每首歌最多唱一次；唱歌必须唱满给定长度；歌曲之间无空隙，结束立即开始下一首。

【输出格式】

- 对每个测试用例输出一行：“Case X: <最大歌曲数> <总时长>”，X 从 1 开始递增。
- “最大歌曲数”计数包含《劲歌金曲》若被选择；总时长是实际演唱的总秒数。
- 各部分以空格分隔，无额外空行。

【样例输入输出（完整引用 + 输入部分解释）】

- Sample Input

```
2
3 100
60 70 80
3 100
30 69 70
```

- Sample Output

```
Case 1: 2 758
Case 2: 3 777
```

- 样例解释：
  - 用例 1：最优是唱第 3 首 80 秒，再唱《劲歌金曲》678 秒，共 2 首、总时长 758。
  - 用例 2：唱第 1、2 首 30+69=99 秒后还剩 1 秒，可再唱《劲歌金曲》678 秒，共 3 首、777 秒；若唱第 1、3 首 30+70=100 秒则无法再唱《劲歌金曲》。

【关键假设 / 陷阱】

- 《劲歌金曲》只能唱一次；其长度固定 678 秒，若时间足够可在其他歌之后再唱。
- 目标是先最大化歌曲数量，再在数量并列时最大化总时长（因歌曲间无停顿）。
- 歌曲长度上限仅“<3 分钟”而非 180 秒闭区间；时间上限 t 可大到 10^9，需注意溢出。
- 输入保证总长度大于 t，意味着至少有一种选择无法全唱完所有歌。
- 输出格式固定带 “Case k:”，注意编号从 1 递增，无额外空行或多余空格。

【解法提示（可选）】

- 先做 0/1 背包在 (n×t) 不可行的情况下，可用 DP 按时间枚举到 t-1 秒，找最多歌数与最优时长，再判断能否加上 678 秒的《劲歌金曲》；也可将《劲歌金曲》视作最后附加。
- 可按“唱几首、用时”排序的 DP 状态，或用二维 DP 保留（用时，歌曲数）最优。
- 时间 t 较大时可利用只需关注 t-1 以内的时间（因需留 678 秒）来减小状态。
